# CLAUDE.md (Backend - Spring Boot)

## 1. 技术栈与职责 (WHAT)
- **核心框架**：Java, Spring Boot, MyBatis（版本写入根 README，保证 Spring Boot / MyBatis starter / Java 兼容）。
- **数据持久化**：MySQL（模板、素材、任务、阶段、历史记录、用户）。结构与种子数据放 `schema.sql` 等初始化脚本，随 Docker Compose 自动执行。
- **文件存储**：本地目录或 Docker 容器数据卷，不依赖对象存储。
- **职责**：模板、素材、制作任务、个人记录的业务与持久化全部由本服务完成。

## 2. 开发与验证命令 (HOW)
在 `backend/` 下：
- **启动应用**：`./mvnw spring-boot:run`
- **运行测试**：`./mvnw test`
- **CI 完整检查**：`./mvnw clean verify`（测试 + 打包）
- **仅打包**：`./mvnw clean package -DskipTests`（本地调试用，不能替代 CI 检查）

## 3. 核心业务规则 (Backend Specific)
- **状态与阶段分开 (R-05)**：
  - `status`：`PENDING`（等待）→ `RUNNING`（处理中）→ `SUCCEEDED` / `FAILED`。
  - `stage`：`CHECKING`（素材检查）→ `GENERATING`（模拟生成）→ `FINALIZING`（结果整理）。
  - 终态（SUCCEEDED / FAILED）不可回退；任何查询都不得改变任务状态。
- **受理与异步 (R-04)**：提交接口校验参数并创建任务记录（`PENDING`）后**立即返回任务 ID**；后台线程池（如 `@Async` + 有界 `ThreadPoolTaskExecutor`）按顺序执行三阶段，关闭页面不影响任务。
- **执行边界与持久化 (R-05)**：
  - 每个阶段开始与结束都单独落库（当前阶段、状态、时间戳），不得把整条流水线或 `sleep` 包在一个事务里。
  - **查询接口只读**，不能通过查询推进任务。
  - 成功后写入可预览的结果地址；失败时写入失败阶段与可读的失败原因。
- **失败模拟与耗时 (R-06)**：
  - 通过配置项（`application.yml` 属性）或仅 dev/test profile 的开发接口，指定“哪个阶段失败”与“各阶段耗时”，可重复触发，不使用随机失败。
  - 失败后立即停止后续阶段并持久化原因；模拟开关不得出现在正式页面或模板字段中。
  - 操作方法写入 README。
- **用户隔离 (R-10)**：所有任务、历史、素材接口都基于当前用户身份过滤，访问他人任务返回 404/403，而不是返回数据。
- **参数与素材校验 (R-03)**：服务端必须严格校验素材数量、类型、大小及制作参数，且以模板定义为准，不信任前端。
  - 类型按文件内容（魔数）判断，不只看 Content-Type 或扩展名。
  - 存储文件名随机化，防路径穿越，不使用用户提供的文件名作为路径。
  - 提交时校验引用的素材确属当前用户且已上传完成。
- **必须有的测试 (R-12)**：阶段执行顺序；某阶段失败后后续阶段不执行且失败阶段与原因被保存；终态不会因后续查询改变；用户之间互不可见。
- **已知边界**：服务重启后不自动恢复执行中的任务，需在 README 中如实说明。

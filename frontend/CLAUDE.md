# CLAUDE.md (Frontend - Next.js)

## 1. 技术栈与职责 (WHAT)
- **框架**：Next.js (App Router), React, TypeScript（版本写入根 README）。
- **核心页面**：
  - `/`：模板列表与分类筛选。
  - `/templates/[id]`：模板详情、素材上传（数量、格式、大小校验）、预览/替换/移除。
  - `/history`：个人历史任务、处理阶段、成功结果预览或失败原因查看。
- **后端调用**：业务与持久化全在 Java 后端，前端不实现业务逻辑。API base URL 通过环境变量配置（浏览器访问与容器内服务端访问地址可能不同，需在 `.env.example` 中分别说明）。

## 2. 开发与验证命令 (HOW)
在 `frontend/` 下，`package.json` 必须提供以下脚本：
- **开发服务**：`npm run dev`
- **Lint**：`npm run lint`
- **类型检查**：`npm run typecheck`（`tsc --noEmit`）。Lint 不等于类型检查，两者都要跑。
- **测试**：`npm test`
- **生产构建**：`npm run build`

## 3. 核心业务规则 (Frontend Specific)
- **三层状态，不要混为一个状态机 (R-07)**：
  - 素材位：未选择 / 上传中 / 上传成功 / 上传失败（每个上传位独立）。
  - 表单：提交请求中（仅限提交接口返回前）。
  - 任务（来自后端）：等待 / 处理中 / 成功 / 失败，并展示当前阶段、失败原因或结果。
  - 任务受理成功后立即展示任务，按钮不得继续停留在“提交中”。
- **多任务与轮询生命周期 (R-08)**：
  - 允许连续创建多个任务，状态、阶段、错误、结果按任务 ID 隔离存储，互不干扰。
  - 自动跟踪未完成任务；任务进入终态后停止对其跟踪；没有待处理任务时不轮询。
  - 离开页面、组件卸载、切换用户时必须清理定时器、订阅与进行中的请求（AbortController 或请求序号），旧响应不得覆盖当前用户或其他任务的数据。
- **查询异常恢复 (R-07)**：查询接口暂时不可用属于请求异常，**绝不能**把任务标记为执行失败；保留已有任务信息并提供重试入口。
- **刷新恢复 (R-09)**：页面刷新后从后端拉取历史并继续跟踪未结束任务，不依赖仅存于内存的状态。
- **页面反馈 (R-03)**：模板详情与列表必须处理 加载中、空数据、请求失败、模板不存在（404）。素材未就绪或提交中，提交按钮禁用，防止重复提交。
- **预览资源**：`URL.createObjectURL` 创建的地址在替换、移除、卸载时必须 `revokeObjectURL`；预览仅用于展示，提交的必须是服务端已接收的素材。
- **可访问性与小屏 (R-11)**：使用语义化元素（button、label、dialog）；上传位与图标按钮提供 `aria-label`；保留键盘焦点样式；小屏下主要流程可操作。
- **必须有的测试 (R-12)**：多个任务状态互不串扰；查询异常与任务失败被区分（查询失败后任务仍保持原状态）。
